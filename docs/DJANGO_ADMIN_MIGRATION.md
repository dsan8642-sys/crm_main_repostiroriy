# Единая админка SwimCRM

## Правило работы

Ежедневная работа администратора выполняется только в SwimCRM. Django admin остаётся закрытым техническим резервом для сопровождения и аварийного восстановления: его не используют для клиентов, расписания, оплат или настроек.

## Карта переноса

| Раньше в Django admin | Теперь в SwimCRM |
| --- | --- |
| Клиенты, родители, дети, согласия | `Клиенты` и карточка клиента |
| Тренеры | `Тренеры` и профиль тренера |
| Группы, типы абонементов | `Группы`; `Настройки -> Справочники` |
| Шаблоны, занятия, участники, лист ожидания | `Расписание` и `Занятие` |
| Посещаемость | `Занятие` и кабинет тренера |
| Начисления, оплаты, квитанции | Карточка клиента и `Платежи` |
| Абонементы, заморозки, списания | Карточка клиента |
| Шаблоны и правила уведомлений, тихие часы, логи | `Настройки -> Уведомления` |
| Схемы, ставки, назначения и периоды зарплаты | `Тренеры` и `Настройки -> Зарплата` |
| Локации и типы занятий | `Настройки -> Справочники` |
| Языки, ключи и переводы | `Настройки -> Языки` |
| Журнал аудита, история импортов, статусы 2FA | `Настройки -> Контроль` |

## Ограничения резервного Django admin

- не открывать для обычных операционных задач;
- не удалять исторические платежи, посещения или журнал аудита;
- доступ защищён отдельной 2FA-проверкой в production;
- настройки 2FA не показывают секреты в интерфейсе SwimCRM: их первичная выдача остаётся защищённой процедурой сопровождения.
