# SwimCRM RODO/GDPR operations

Этот документ фиксирует рабочие правила обработки персональных данных в SwimCRM.
Он не заменяет юридическую политику юриста/бухгалтера, но задаёт технический
регламент для эксплуатации.

## Данные и сроки хранения

| Данные | Где хранятся | Срок | Удаление |
|---|---|---|---|
| Клиент: имя, email, телефон, Telegram ID | `ParentAccount`, `User` | Пока аккаунт активен | Анонимизация через `anonymize_parent_account` |
| Участник: ФИО, email, группа, медданные, экстренный контакт | `Student` | Пока участник активен + срок поддержки истории | Анонимизация через `anonymize_parent_account` |
| Согласия | `Consent` | Пока существует аккаунт/история согласий | Отзываются при анонимизации |
| Посещаемость и абонементы | `AttendanceRecord`, `Subscription`, `SessionLedgerEntry` | Долгосрочно как операционная история | Персональные поля участника анонимизируются |
| Начисления и платежи | `Charge`, `Payment` | Долгосрочно по бухгалтерским требованиям Польши | Сохраняются как финансовые факты |
| Файлы чеков | `ReceiptFile.file` | `RECEIPT_RETENTION_DAYS`, по умолчанию 30 дней | Автоочистка задачей `purge_expired_receipts` |
| Журнал действий | `AuditLogEntry` | Минимум срок эксплуатации CRM; финальный срок утверждает владелец | Записи неизменяемые |

## Право на удаление / анонимизацию

Для запроса клиента на удаление данных используется серверная операция:

```powershell
python manage.py shell
```

```python
from accounts.models import ParentAccount
from accounts.privacy import anonymize_parent_account
parent = ParentAccount.objects.get(id=<ID>)
anonymize_parent_account(parent, actor=<ADMIN_USER>)
```

Операция:

- очищает контакты клиента;
- отключает пользовательский аккаунт;
- очищает ФИО/email/медданные/экстренные контакты участников;
- деактивирует участников;
- отзывает согласия;
- удаляет файлы чеков;
- сохраняет бухгалтерские факты, посещаемость, начисления, платежи и журналы.

## Доступы

- Администратор: полный доступ, в production требуется 2FA.
- Тренер: только свои занятия/группы через API.
- Клиент: только свой аккаунт и привязанные профили участников через API.
- Массовые рассылки проходят через consent-aware уведомления.

## Утечки данных

При подозрении на утечку:

1. Отключить скомпрометированного пользователя (`is_active=False`).
2. Сменить `SECRET_KEY`, пароли БД/API и доступы хостинга, если они могли утечь.
3. Сохранить копии `AuditLogEntry` и логов reverse-proxy/app.
4. Определить затронутых субъектов данных.
5. Уведомить владельца продукта и юриста/инспектора RODO.
6. Подготовить уведомление для органа/субъектов данных, если требуется законом.
7. Зафиксировать инцидент, причину, затронутые данные и меры предотвращения.

## Production checklist

- `DEBUG=0`
- сильный `SECRET_KEY`
- `ALLOWED_HOSTS` только реальные домены
- HTTPS/TLS и secure cookies
- `TRUST_PROXY_SSL_HEADER=1`, только если reverse-proxy гарантированно выставляет header
- `ADMIN_2FA_REQUIRED=1`
- регулярный PostgreSQL backup
- регулярная проверка восстановления backup
- `run_due_jobs` через Celery beat или cron
