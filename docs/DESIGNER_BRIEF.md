# SwimCRM: документ для дизайнера интерфейсов

Документ описывает, какие экраны, поля, действия и состояния нужны для трёх версий продукта:

- администратор;
- тренер;
- клиент.

Цель дизайна — не лендинг, а рабочая CRM для школы плавания. Интерфейс должен быть спокойным, плотным, понятным для ежедневной работы: быстро найти клиента, отметить посещаемость, проверить оплату, увидеть расписание и долги.

## Общий контекст

SwimCRM — веб-CRM для частной школы плавания в Польше. Пользователи:

- администраторы школы;
- тренеры;
- клиенты: взрослые участники или аккаунты семьи для детей.

Участник занятий может быть ребёнком или взрослым клиентом. У ребёнка нет отдельного логина: в систему входит клиентский аккаунт семьи. Взрослый клиент может иметь один аккаунт без детских профилей.

Важные правила:

- деньги в PLN, суммы отображаются в нормальном виде, например `240,00 zł`;
- онлайн-оплаты нет;
- клиент только загружает подтверждение оплаты, администратор проверяет;
- абонементы считаются через историю движений занятий, а не через редактируемое поле “остаток”;
- тренер не может быть назначен на два занятия одновременно;
- медданные и экстренный контакт ребёнка важны;
- интерфейс должен учитывать RODO/GDPR: меньше лишних данных, понятные согласия, аккуратная работа с чеками.

## Роли

| Роль | Основная задача | Что видит |
|---|---|---|
| Администратор | Управляет всей школой | Все клиенты, тренеры, группы, расписание, оплаты, отчёты, импорт/экспорт, уведомления |
| Тренер | Ведёт занятия и отмечает посещаемость | Только свои занятия, группы и учеников на этих занятиях |
| Клиент | Следит за своим аккаунтом, оплатами и расписанием | Только свой аккаунт и привязанных участников, их абонементы, расписание, посещаемость и платежи |

## Администраторская версия

### 1. Обзор

Назначение: быстрый операционный экран на сегодня.

Поля и блоки:

| Блок | Поля |
|---|---|
| Сегодня | количество занятий сегодня, ближайшее занятие, тренеры сегодня, отменённые занятия |
| Финансы | неоплаченные начисления, просрочки, платежи на проверке |
| Клиенты | активные клиенты, неактивные клиенты, новые за период |
| Абонементы | скоро заканчиваются, мало занятий осталось, истекли |
| Уведомления | в очереди, отправлено, ошибки |

Действия:

- перейти к расписанию на сегодня;
- открыть платежи на проверке;
- открыть должников;
- открыть список “скоро оплата”.

Состояния:

- пустой день без занятий;
- есть ошибки уведомлений;
- есть платежи на подтверждение;
- есть критичные просрочки.

| Группа | название группы |
| Тренер | тренер группы |
| Статус | активен / неактивен |
| Баланс | долг / переплата / ноль |
| Абонемент | тип, остаток, дата окончания |

Фильтры:

- активные / неактивные;
- должники;
- группа;
- тренер;
- скоро оплата;
- абонемент истёк;
- остаток занятий меньше N.

Поиск:

- имя ребёнка;
- фамилия ребёнка;
- телефон семьи;

Карточка ребёнка:

|---|---|

| Экстренный контакт | имя, телефон |

Действия:

- перевести в другую группу;
- деактивировать;
- открыть клиентский аккаунт;
- создать начисление;
- добавить платеж;

- заморозить абонемент;

Важно для дизайна:

- медданные должны быть заметны, но не кричащими;
- анонимизация должна иметь явное подтверждение, это необратимое действие.

### 7. Посещаемость

Экран занятия:

| Поле | Комментарий |
|---|---|
| Дата и время занятия | сверху |
| Группа/ученик | группа или индивидуальный ученик |
| Тренер | кто ведёт |
| Локация | бассейн |
| Список учеников | таблица |

Строка ученика:

| Поле | Комментарий |
|---|---|
| ФИО | ученик |
| Телефон семьи | опционально для админа, осторожно для тренера |
| Статус | 4 варианта |
| Списание | списывает / не списывает |
| Комментарий | текст |
| Кто отметил | пользователь |
| Когда отметил | дата/время |

Статусы:

- присутствовал — списывает занятие;
- отсутствовал — списывает занятие;
- отсутствовал по уважительной причине — не списывает;
- перенос — не списывает.

Действия:

- отметить всех;
- изменить статус;
- добавить комментарий;
- сохранить;
- посмотреть историю ученика.

Важно:

- дизайнер должен явно показать, какие статусы списывают занятие;
- изменение статуса не редактирует старую запись журнала, а создаёт корректировку.

- 2FA настроена, но не подтверждена;
- 2FA активна;
- нужно сбросить устройство.

## Версия тренера

### 1. Мои занятия

Список:

| Поле | Комментарий |
|---|---|
| Дата | день |
| Время | начало-конец |
| Группа | название |
| Локация | бассейн |
| Количество учеников | ожидаемые |
| Статус | запланировано / отменено / прошло |

Фильтры:

- сегодня;
- неделя;
- период;
- группа;
- отменённые.

Действия:

- открыть занятие;
- отметить посещаемость;
- добавить комментарий.

Тренер не должен видеть:

- чужие занятия;
- финансовые данные;
- полные админские действия.

### 2. Занятие тренера

Поля занятия:

- дата;
- время;
- группа;
- локация;
- лимит;
- комментарий.

Список учеников:

| Поле | Комментарий |
|---|---|
| ФИО | ребёнок |
| Экстренный контакт | желательно доступен, если политика школы разрешает |
| Медицинская заметка | кратко/осторожно |
| Статус посещаемости | 4 статуса |
| Комментарий тренера | текст |

Действия:

- отметить присутствовал;
- отметить отсутствовал;
- отметить уважительная причина;
- отметить перенос;
- сохранить.

Важно:

- статусы “присутствовал” и “отсутствовал” списывают занятие;
- тренер не продлевает абонемент;
- тренер не меняет платежи;
- тренер не переносит занятие сам, если это запрещено бизнес-правилом.

### 3. Группы тренера

Список групп:

- название;
- расписание;
- количество учеников;
- ближайшее занятие.

Карточка группы:

- ученики;
- ближайшие занятия;
- история посещаемости.

## Версия клиента

### 1. Главная

Блоки:

| Блок | Поля |
|---|---|
| Участники | карточки привязанных участников: дети или взрослый клиент |
| Следующая тренировка | дата, время, группа, локация |
| Абонемент | тип, остаток, дата окончания |
| Оплата | следующий платёж, статус, долг |
| Уведомления | важные сообщения |

Если у клиента несколько привязанных участников, нужен переключатель участника.
Технически взрослый клиент хранится как участник с признаком is_account_holder=true. Это нужно, чтобы абонементы, посещаемость, начисления и платежи работали одинаково для взрослых и детей.


### 2. Карточка участника

Поля:

- ФИО;
- группа;
- тренер;
- дата рождения;
- статус;
- текущий абонемент;
- остаток занятий;
- дата окончания;
- история посещений;
- история оплат.

Клиент не редактирует критичные данные напрямую, если школа это не разрешила. Можно показать “обратиться к администратору”.

### 3. Расписание клиента

Поля занятия:

| Поле | Комментарий |
|---|---|
| Участник | если участников несколько |
| Дата | дата |
| Время | начало-конец |
| Группа | группа |
| Тренер | тренер |
| Локация | бассейн |
| Статус | запланировано / отменено |

Фильтры:

- участник;
- неделя;
- месяц;
- будущие / прошедшие.

Клиент не может:

- сам записать участника;
- сам перенести занятие;
- отменить занятие.

### 4. Абонемент клиента

Поля:

- участник;
- тип абонемента;
- дата начала;
- дата окончания;
- остаток занятий;
- заморозки;
- история движений.

Действия:

- заявка на продление;
- связаться с администратором.

Важно:

- остаток занятий вычисляемый;
- история списаний должна быть понятной: покупка +8, занятие -1, корректировка +1.

### 5. Оплаты клиента

Поля:

| Поле | Комментарий |
|---|---|
| Начисления | что нужно оплатить |
| Сумма | PLN |
| Срок оплаты | дата |
| Статус | ожидает оплаты / частично / просрочено |
| Платежи | история |
| Чеки | загруженные подтверждения |

Загрузка чека:

Поля:

- участник;
- сумма;
- дата оплаты;
- способ оплаты;
- комментарий;
- файл PDF/JPG/PNG.

Состояния:

- чек загружается;
- чек принят и ожидает проверки;
- платёж подтверждён;
- платёж отклонён;
- файл слишком большой;
- неверный формат файла.

### 6. Посещаемость клиента

Поля:

- дата занятия;
- участник;
- группа;
- тренер;
- статус;
- списано занятие или нет;
- комментарий.

Фильтры:

- участник;
- период;
- статус.

### 7. Уведомления и согласия

Поля:

- согласие на обработку данных;
- email-уведомления;
- SMS;
- Telegram;
- дата выдачи;
- дата отзыва;
- версия политики.

Действия:

- включить/отключить канал;
- отозвать согласие;
- подключить Telegram.

Важно:

- нельзя делать согласия незаметными;
- отзыв согласия должен быть понятным;
- для обязательной обработки данных может потребоваться пояснение “обратитесь к администратору”.

### 8. Профиль клиента

Поля:

- ФИО;
- телефон семьи;
- email;
- Telegram;
- участники;
- пароль;
- согласия.

Действия:

- изменить контактные данные, если школа разрешает;
- сменить пароль;
- запросить удаление/анонимизацию данных.

## Общие состояния интерфейса

Нужно предусмотреть:

- загрузка данных;
- пустой список;
- нет прав;
- ошибка сервера;
- ошибка валидации;
- успешное сохранение;
- конфликт расписания;
- файл чека отклонён;
- действие необратимо;
- данные уже были изменены другим пользователем.

## Важные ограничения для дизайна

- Не делать маркетинговый лендинг вместо CRM.
- Не прятать критичные статусы: долг, просрочка, платеж на проверке, отменённое занятие.
- Не смешивать начисления и платежи.
- Не давать клиенту действия, которых нет в бизнес-правилах: самостоятельная запись/перенос занятия.
- Не показывать тренеру финансовые данные клиента.
- Не показывать клиенту чужих участников/группы/платежи.
- Не проектировать онлайн-оплату: её нет в scope.
- Для таблиц нужны фильтры и поиск, а не только карточки.
- Все денежные суммы показывать с валютой.
- Все даты/время — в локали Europe/Warsaw.

## Минимальный MVP интерфейса

Если делать поэтапно, сначала нужны:

1. Админ: клиенты, расписание, посещаемость, оплаты на проверке, должники.
2. Тренер: мои занятия, экран отметки посещаемости.
3. Клиент: главная, расписание, абонемент, оплаты, загрузка чека.
4. Админ: отчёты и экспорт.
5. Админ: уведомления и массовые рассылки.
6. Настройки безопасности/RODO.
